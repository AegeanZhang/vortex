# Review 检查清单

根据变更范围选择适用项，不要求纯文档修改机械执行所有运行时检查。

## 范围与架构

- 改动是否只包含一个明确目的，是否夹带无关重构或格式化？
- crate 职责和依赖方向是否符合 [`../architecture/overview.md`](../architecture/overview.md)？
- 是否误让产品代码依赖 `playground/` 或让 `vortex-core` 依赖具体实现？
- 行为、设计与用户手册是否一致，是否把尚未实现的目标写成当前能力？

## 正确性与验证

- 是否覆盖成功、失败、取消、超时和边界输入？
- 是否执行了 [`testing.md`](testing.md) 中与改动相关的命令，并如实记录结果？
- 未实现的命令是否明确失败并返回非零退出码，而不是用占位输出伪造成功？

## 安全与兼容性

- 密钥、认证头和用户内容是否可能进入日志、错误、测试快照或 Git？
- 文件、Shell 与 MCP 操作是否统一经过权限和沙箱策略？
- CLI 参数、配置格式、事件 schema 或 Provider 行为是否造成兼容性变化？
- TUI 变化是否验证了终端恢复，并准备截图或录屏？
